# Project UI handoff development observations

This local development change adds an opt-in adopter-native handoff command to
`setup-ui`; it does not change Pstack's explicit skill invocation policy or any
release-controller pin. Product criteria and evidence coverage remain adopter-owned.

## Observed boundary

A fresh-context internal worker received an ordinary request to make a synthetic
HTML account-deletion control visually clear, retaining its label. Its scratch
project had a durable `AGENTS.md` instruction and a project command invoking the
candidate `design_evidence.py handoff`. No model/session override was selected.
The worker changed the control, ran the native project command, observed the
missing current packet failure, and reported the handoff blocked. The command's
invocation marker was independently read afterward. This is one known negative
development probe, not a holdout or a comparative quality result.

Separate deterministic tests execute native subprocesses and a new Python process
against retained synthetic evidence. They cover complete evidence, failed checks,
source mutation/deletion, changed Git revision, non-Git proposal drift, missing
review record, self-session labels, changed notes/transcript/response, mismatched
packet logs, incomplete command coverage and unresolved review questions.
Their one-pixel images and fabricated test reviewer records are explicitly
fixtures, not actual rendered review or proof of reviewer independence.

A later independent code review found that a successful silent native command
produced an empty log that the packet preparation correctly rejected. Native check
logs now carry a deterministic command/exit-status envelope and preserve stdout
and stderr bytes separately. Regressions cover silent-success handoff, binary
output retention, and continued rejection of missing or tampered logs. The repair
changes the package digest; observations of earlier bytes remain development
diagnostics, not compatibility evidence for the repaired package.

An independent code reviewer found a packet/native-log binding gap and loss of
receipts when a native check deleted a required source file. Both were repaired,
regression-tested and rechecked. That review did not review rendered product UX.

## Rendered positive-path probe

A disposable non-Git delivery-day proposal was rendered with an already-installed
Chromium at 1280 and 390 pixels. The actual native command checked overflow,
keyboard activation of the changed day, and retaining the original day. It
captured pending/resolved states at both widths. An initial module-path error and
a sandbox browser-launch failure were retained; the approved native browser retry
passed without installation or a server.

A separate fresh-context reviewer viewed all four actual PNGs one at a time,
saving unaided notes before each subsequent screen and before reading the contract,
brief, native log and fixture reference. Its saved response found no meaning or
layout issue. The candidate handoff accepted the exact source snapshot, native
logs and response record. A subsequent source change and a copied review with an
unresolved question both failed; the byte-restored control passed again. The
reference was a synthetic fixture composition, not user-approved product design.
The retained reviewer dispatch/result is not a signed host transcript.

## Not established

No multi-project automatic setup trial, matched upstream comparison, or universal
fresh-thread compliance claim is made. The native command checks consistency and fails closed when its required
evidence is absent; it cannot authenticate arbitrary reviewer labels or prevent
an assistant from sending a message. Actual fresh-review execution and first-look
order must be preserved and inspected, not inferred from schema acceptance.
