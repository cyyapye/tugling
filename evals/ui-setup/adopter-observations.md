# Configured-adopter setup trial

A fresh-context executor invoked `setup-ui` against an existing three-portal
application with a shared UI library and a separate marketing app. The adopter
already had an uncommitted evidence profile and lint integration. This exercises
assessment and end-to-end setup replay, not installation into a new project.
The candidate package and project-file hashes were frozen before execution;
private criteria and observer artifacts were not supplied to the executor.

## Observed outcome

- Each portal's normal lint command rejected two prohibited style overrides;
  repaired compositions passed. The existing 15 policy controls also passed.
- All 15 native browser tests passed after supported environment recovery.
  Twelve current captures were retained. The independent reviewer inspected
  ten screen images across five states at both viewports and one reference.
- The full native gate passed with the repository's documented public build
  origins: 1,589 Python tests, 267 app unit tests, and four app build/check paths.
- Profile replay reported `UNCHANGED`; all 313 evidence inputs and 17 pre-existing
  setup files remained byte-identical. Only the canonical assessment was updated.
- The assessment recommended verification coverage, an existing component variant,
  and primitive reuse, while retaining domain-specific bodies locally.
- Independent review accepted theme, responsiveness, and hierarchy but returned
  `CHANGES_REQUESTED`. Two accepted findings and source-confirmed fixture
  inconsistencies remain follow-ups. Native success did not erase that outcome.

The original sandbox/browser-install failures and a full-gate attempt missing
public build variables were preserved. Tests, assertions, retries, timeouts,
configuration and product sources were not weakened or changed. One missing
browser runtime was installed through the app's existing test CLI.

## Handoff correction

The executor initially restricted the reviewer to packet files, but the helper
references project contracts by path and hash without copying them. After the
reviewer saved all unaided notes, the executor granted read access to only those
referenced contracts. The original handoff and clarification remain preserved.
This exposed a reusable instruction gap: the project-evidence workflow now makes
that read scope explicit while preserving the first-look order.

The original reviewer response had two extra schema fields. It was preserved,
and a schema-only repair moved those fields to an addendum without changing any
judgment. The corrected response validated as `CHANGES_REQUESTED`. There was no
rerun to solicit a cleaner opinion and no product repair during this trial.

## Limits

This is one configured-adopter run using the session's model and same-family
review, with parent reconciliation. It is not a matched Pstack comparison, a
fresh-project installation, universal UI coverage, general defect-detection
proof, or release approval. Authenticated owner transactions, full keyboard
accessibility, public mobile rendered review, marketing browser journeys,
production data, remote CI and deployment remain outside the observed boundary.

The small handoff instruction correction followed the frozen trial; the entire
adopter run was not repeated against that later text. The corrected access
sequence itself was observed in the retained trial. Raw images, replies,
project paths, source snapshots, identities, and detailed execution evidence stay
in the adopter's ignored local artifacts and private observer storage. No
certification report, controller pin, published package, or user installation
was changed.
