# Tugling 0.10.0 release candidate

This is an unreleased local candidate. Published stable remains 0.9.1. No
certificate or stable promotion is created by these development observations.

## Package

The source pin advances from `101b274dd991f694e1f7024be2157e5f3adf07de` to
`c742dd61706fbacc1b95f1a20b7b988cf096ce6c`. The bundle retains all 58 current
Pstack skill names, its 24 principles, playbooks, helper sources and full MIT
license. Codex metadata, invocation, scope, model inheritance and unavailable
host capabilities remain explicit adaptations in the source inventory.

`setup-ui` is a separately attributed, explicitly invoked Tugling addition.
It carries forward the existing guided assessment, approval, implementation,
verification and replay flow. A configured-adopter trial supplied narrow lessons
about command-level lint enforcement, actual evidence-input coverage, supported
screenshot platforms, settled recovery captures and reviewer contract access.
Project rules and component policy remain in adopter repositories.

## Local completion gate

`make verify` passed with 364 native tests, behavioral/UX diagnostic validation,
clean-package reconstruction of all 59 skills, and release-configuration
validation. The successful host run preserved the separate sandbox failures.
This is local evidence; remote CI and its runtime budget remain unverified.

## Development observations

- A fresh native local-marketplace installation exposed the complete candidate.
  The help and CLI bug-fix tasks passed their automated checks. Trace inspection
  confirmed successful skill and adapter reads; the delivered regression rejected
  the original implementation and the native CLI gate passed.
- A separate configured-adopter walkthrough exercised the final setup skill with
  the configured model and reasoning effort. Product inputs, dependencies, lint
  policy and profile were unchanged. Prohibited-style probes failed through the
  ordinary app lint commands; repaired controls passed. Unsupported raw controls
  and inline styles were reported without extending policy. Profile replay was
  unchanged and component refactors stayed skipped.
- The first browser attempts could not fetch the application's public fonts.
  Their original failures remain preserved. A separate host replay passed all
  15 native browser checks and retained 12 current captures. The scoped frontend
  snapshot cannot run the adopter's whole-repository Python gate; that limitation
  is separate from the passing UI checks.
- A fresh rendered reviewer inspected all 12 images and seven referenced
  contracts, saving unaided notes first. The actual response validated as
  `CHANGES_REQUESTED`: missing practice identity on a public form, undisclosed
  synthetic operator data, conflicting setup/wallet states across screens, and
  inconsistent aggregate counts. Captured fidelity, responsiveness and hierarchy
  were acceptable. Those application findings remain open; no product repairs
  or new review outcome are claimed.
- The upstream statechart suite's sandbox attempt had cache-write and process
  access failures. A contained host run passed 266 tests, with one relative-link
  fixture failing because macOS temporary-directory aliases were mixed. That
  unchanged test passed with a canonical temporary path. The 67 checks requiring
  a live TLC/Java runtime were skipped; no live model-checker result is claimed.

Raw runs, project source, screenshots, reviewer responses, exact runtime receipts
and token accounting remain outside Git. These are bounded compatibility and
adopter observations, not a matched enhancement comparison, fresh-project setup
proof, full-catalog behavioral certification or deployment evidence.

The sandboxed local gate could not bind loopback sockets for its native server
lifecycle tests. The unchanged focused interruption/cleanup case passed with host
permissions. Original sandbox failures remain separate from the host gate.
The rendered reviewer used inherited session settings; no cross-family model
comparison or enhancement advantage is claimed.

## Release boundary

The local source inventory and comparison tooling now distinguish upstream and
local skills. Synthetic release repositories omit the statechart replay corpus
while preserving their Git identity and authority assertions; the complete
shipped bundle remains covered by source and clean-room checks. These evaluator
and fixture changes require separate controller review before certification.
No approved controller pins or release permissions have changed. A maintainer
must still review exact-package workflow evidence, public installation and the
normal certification and protected-promotion requirements.
