# Reviewed compatibility evidence for 0.9.0

[pstack-review.json](pstack-review.json) binds fresh observed Pstack workflows to
the exact 0.9.0 package. It is a review input, not a certificate or promotion
approval. The released baseline remains 0.8.0.

## Change and opt-in scope

The candidate adds project-owned UI evidence setup, catalogue/agent-guide
maintenance, stack-appropriate style enforcement and independent rendered review.
Existing adopter contracts may opt into the optional project-setup and
project-evidence references. The 54 skill entry points and Pstack's explicit
invocation policy remain unchanged. Setup does not install a global plugin,
replace a project's component library or authorize publication.

The [UI trial](../../../docs/ui-evidence-evaluation.md) separately records actual
profile initialization/repeat/conflict handling, a scoped official shadcn linter
probe that fails then passes after correction, and fresh rendered reviewers that
find two seeded defects and review their repairs. The trial used the same evidence
helper bytes shipped here. Its known-defect exercise does not establish general
judge accuracy, better design judgment or one-shot delivery.

## Exact-package observations

On October 27, 2026, 15 builder attempts covered 14 development tasks and all eight
required workflow areas. Each used a fresh synthetic repository and native local
plugin installation in an isolated home. Runtime: Codex CLI
`0.164.0-alpha.11.1`, configured `gpt-6.1-sol`, reasoning effort `xhigh`.

| Area | Observed result |
| --- | --- |
| Discovery and setup | Help, natural setup discovery and short-session setup preserve settings and distinguish runnable checks from correct behavior. |
| Planning scope | A source-grounded two-phase plan stays in the response without edits or test execution. |
| Repair and regression | Reproduces the CLI defect before repair; regressions reject the original; native and real CLI checks pass after repair. |
| Verification honesty | Finds the documented full-name defect despite the existing green unit suite. |
| Capability fallbacks | Architecture, comparison and input review use disclosed sequential fallbacks; unavailable PR state stays unknown. |
| History scope | Uses present source/history without inventing missing conversations or prior decisions. |
| Skill authoring | Initial delivery is incomplete; a narrowly granted repeat creates and executes the reusable workflow and preserves its evidence. |
| Idle scope | Returns the requested acknowledgement with no tool calls or changes. |

The original authoring attempt passed the greeting oracle but failed three of six
semantic criteria: no reusable skill, feature map or executed workflow evidence.
Its response reported an approval rejection for the protected `.agents` path;
that explanation is self-report, while the absent artifacts independently prove
the failed delivery. The repeat pre-created and explicitly granted only the
requested synthetic skill directory. Task, rubric, package, model and effort
stayed fixed; the timeout changed from 300 to 600 seconds. It passed all six
criteria and ran the actual reusable helper successfully. The original failure
and usage remain in the report. This is an environment repeat, not a matched
performance comparison. The builder disclosed a missing PyYAML dependency in
its separate skill validator rather than claiming that validator passed.

Three fresh same-family reviewers saw blinded output/source bundles. They
recorded 41 passing criteria, three failures and 19 requiring trace evidence.
The parent inspected command order, actual skill reads, real verification runs,
changed paths and runtime metadata to resolve those 19; original reviews were
preserved. Final accounting is 60 passing and three failed criteria across all
attempts, with the failed attempt resolved by the retained successful repeat.
No unresolved criteria remain. Private delivery inventories and unchanged
blinded inputs were checked before assembling the sanitized report.

Builder usage was 2,746,086 input tokens, including 2,250,752 cached, and 53,961
output tokens. Author/reviewer usage is excluded from that report. These are known
development tasks in a small fixture, not unseen holdouts, coverage of every
skill, an enhancement comparison or real multi-agent execution evidence.

## Native verification

`make verify` passed all 360 tests, source/package validation, behavioral/UX suite
structure checks, clean-package checks and release configuration. The final
exact-package report also passed release validation after it was assembled.
`actionlint` 1.7.12 passed. No assertions, deadlines or retries were weakened.

The earlier sandboxed full run had six failures and one error because synthetic
servers could not bind loopback ports. The affected modules passed with loopback
permitted, followed by the complete passing native gate. Those failed logs are
retained privately. Structural checks and a valid review report do not approve a
release or prove the UI judgments universally correct.

## Remaining publication boundaries

Record successful PR CI and a credential-free installation of the exact public
candidate commit on the release PR before merging. No model call is needed for
that installation check. After merge, certification still requires exact-current-
main verification and separate acceptance of this report's original byte digest.

Controller review must cover `scripts/pstack_profiles.py` (external documentation
links are references, not local dependencies), `tests/test_design_evidence.py`,
and the changed source inventory. Both existing controller pins remain unchanged.
Review and approve any new controller commit/tag separately under the
[controller procedure](../../../docs/release-controller.md), then approve the
exact report digest for [certification](../../../docs/release-certification.md).
Protected stable promotion and its installation canary remain separate actions.

Private hashes identify retained evidence; they neither reproduce that evidence
nor prove reviewer independence or judgment accuracy. The maintainer's review of
the underlying evidence owns that trust boundary. Raw traces, local paths,
credentials and adopter records are not committed.
