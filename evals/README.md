# Evaluations

Start with the [test audit](test-audit.md). The Pstack port preserves familiar
explicit skill invocation. The old declarative routing cards were removed;
validating their JSON never exercised Codex discovery or routing.

Start development evaluation with [Pstack's attributed Eval method](pstack/method.md).
[`pstack/`](pstack/README.md) supplies fresh native installations, ordinary tasks,
hidden criteria, matched package profiles and blinded review bundles. Execution
traces support a separate audit of actual behavior.

The [addition assessment](pstack/additions-assessment.md) records why optional
Tugling guidance is dormant, which Pstack methods own those tasks, and which
failure cases remain available for future comparisons.

[`behavioral/`](behavioral/README.md) retains the legacy questionnaire, executable
regression diagnostics and controlled release matrix. Its multiple-choice scores
do not establish Pstack skill quality or an enhancement advantage.

Structural checks, observed Pstack workflows, synthetic comparisons, project
dogfood, and the full promotion gate establish different kinds of evidence.

[`ux/`](ux/README.md) adds local correction-burden diagnostics with frozen task
inputs, immutable first deliveries, anonymized review bundles and separate repair
scores. Its known development cases do not certify UX improvement or modify the
approved behavioral promotion matrix.
